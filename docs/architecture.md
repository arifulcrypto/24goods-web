# Architecture: 24goods

**Status:** v0.2 (MVP-0 implemented). Rationale and trade-offs for every change since v0.1 are in [review-v2.md](review-v2.md); the original platform evaluation is in [analysis.md](analysis.md).

**Priorities:**
1. Security
2. Correctness of money and stock
3. Speed from mainland China
4. Developer velocity

## 1. Runtime topology (one host: demo and the MVP-0 single-VPS layout)

```
                 Internet ──► :80/:443  ┌───────────────────────────── edge 10.89.10.0/24 ─────┐
                                        │ web  (Caddy 2.11, 10.89.10.10)                       │
                                        │   /            → /srv/web   (buyer SPA, Vant 4)       │
                                        │   /admin/      → /srv/admin (staff SPA, Element Plus) │
                                        │   /api/*       → api:8000   (SSE: flush_interval -1)  │
                                        │   /mockpay/*   → mockpay:8002  (profile "demo" only)  │
                                        └───────┬───────────────────────────────┬──────────────┘
                                                │                               │
                         ┌──────────────────────▼─────────┐        ┌────────────▼──────────┐
                         │ api  python -m app.serve        │        │ mockpay (dev/test)    │
                         │  :8000 public API   (app_api)   │◄───────│ ZPay simulator        │
                         │  :8081 internal (TLS ask)       │ notify │ redis user: mockpay   │
                         │  vault: PUBLIC key only (seal)  │        └───────────────────────┘
                         │  redis user: api                │
                         └──────┬───────────────┬──────────┘
         backend 10.89.11.0/24  │ internal:true │ (no internet egress)
                  ┌─────────────▼──┐   ┌────────▼──────────────────────────┐   ┌──────────────┐
                  │ postgres 17    │   │ delivery  python -m app.delivery  │   │ redis 7 (ACL)│
                  │ FORCE RLS      │◄──│  outbox consumer + :8001 reveal    │──►│ default: off │
                  │ roles: owner / │   │  vault: PRIVATE keys (only here)   │   └──────────────┘
                  │ api / delivery │   │  DB role app_delivery, redis user  │
                  └────────────────┘   │  delivery (no sess:* access)       │
                                       └────────────────────────────────────┘
```

**Rules:**
- Only `web` publishes a port. Docker-published ports bypass UFW, so nothing else may ever get `ports:`.
- Each container receives **only its own** env file (`deploy/env/<service>.env`, generated by `deploy/bootstrap.sh`).

## 2. Production server allocation (M1)

Unchanged in intent from v0.1:

| Host | Role |
|---|---|
| SoftBank JP | Edge / CN entry: Caddy + CrowdSec; holds no data and no keys |
| IIJ JP | Core: api, delivery, PostgreSQL, Redis |
| US UT | DR / ops: PG replica, pgBackRest repository, monitoring, restore drills; OpenBao later |
| Tencent GZ | CN probe only |

**Starting point:** one domain, standard automatic HTTPS. A second CN entry hostname is added **only if** measured CN latency justifies it.

**Latency rule:** if p99 RTT × DB round-trips exceeds 30% of the 150 ms server-side p95 budget, consider colocating the API with PostgreSQL. This is a manual decision recorded as an ADR, never automatic ([review-v2 §6.3](review-v2.md#63-latency-decision-rule-replaces-5-ms)).

## 3. Components

| Component | Implementation |
|---|---|
| API | FastAPI modular monolith: `auth`, `catalog`, `chat` (+quotes), `orders`, `payments` (notify), `inventory`, `uploads`, `realtime`, `admin`. SQLAlchemy 2 async + asyncpg, Alembic. One process serves the public app (:8000) and an internal app (:8081). |
| Delivery service | Separate process. Outbox consumer (`FOR UPDATE SKIP LOCKED`) plus a Starlette-only internal reveal API. The only holder of private keys. FastAPI/pydantic are not loaded (enforced by test). |
| Jobs | Durable work goes through the PostgreSQL **outbox** (same transaction as the state change). Order expiry runs as an asyncio task in the API. |
| Realtime | **SSE** over Redis pub/sub (`rt:*` channels), with a 15 s heartbeat; clients fall back to polling. Centrifugo is deferred until there is more than one API node or more than ~2k concurrent connections. |
| Frontend | Two static Vite SPAs in one pnpm workspace (`web`: Vant 4, `admin`: Element Plus, `shared`), served by Caddy. **No Node at runtime.** Web initial JS is 77 KB gzip (budget 150 KB). |
| Payments | `PaymentAdapter`-style ZPay adapter on the EPay protocol (`app/payments/epay.py`, `zpay.py`). USDT (BEpusdt) is phase 2. |
| Uploads | Local volume in the demo; a private R2 bucket proxied via the edge in production. Served only through `/api/v1/files/{id}` with authorization. |
| Search | PostgreSQL full-text search + `pg_trgm` |

## 4. Data model (implemented, `migrations/versions/0001_initial.py`)

Every tenant table has `tenant_id`, with **ENABLE + FORCE ROW LEVEL SECURITY** and the policy `tenant_id = current_setting('app.tenant_id')::uuid`. An `after_begin` hook pins the tenant on every transaction, and background jobs pin the tenant per job.

Tables:
- `tenants`, `users`, `agent_status`, `custom_domains`
- `products` (i18n jsonb, `price_minor`, `floor_price_minor`, `delivery_mode`)
- `card_stock` (`blob` bytea, `fingerprint`, `kid`, `status`, `order_id`)
- `conversations`, `messages` (bigserial ids, `UNIQUE(sender_id, client_msg_id)`), `attachments`
- `quotes` (HMAC-signed, versioned)
- `orders` (random `order_no`, `version`, `quote_id UNIQUE`), `order_events`
- `payments` (`UNIQUE(channel, gateway_trade_no)`, `UNIQUE(order_id)`)
- `deliveries`
- `ledger_entries` (append-only by grants; a deferred trigger enforces Σ = 0 per transaction)
- `outbox`, `audit_log`

Money is stored as `bigint` minor units plus `currency`. Floats are never used.

**Roles** (non-superusers; the superuser exists only for initdb):

| Role | Privileges |
|---|---|
| `app_owner` | Owns the schema; `CREATEROLE`; runs migrate and seed; bound by FORCE RLS |
| `app_api` | `INSERT` on `card_stock`, but **no `SELECT` on `blob`** (column grant); normal CRUD elsewhere |
| `app_delivery` | Reads `blob`; updates only `status`/`order_id`; writes deliveries, events, messages, ledger, audit |

## 5. Card-key vault and key lifecycle

- **Crypto** (`app/core/cardvault.py`): one DEK per card, AES-256-GCM. The DEK is wrapped with X25519 ECDH + HKDF-SHA256 + AES-GCM. AAD = (tenant, product, card_id), so a row swap fails to decrypt. A keyed, tenant-scoped HMAC fingerprint provides dedup.
- **Isolation, four layers:**

| Layer | API | Delivery |
|---|---|---|
| Process | `CardSealer` with public keys only; refuses to start if a private-key file is configured | `CardOpener`, the only process with private keys |
| Secret | `vault_public_keys` | `vault_private_keys`, mode 0400, owned by the container uid |
| Database | No `SELECT` on `blob` | Reads `blob` |
| Network | edge + backend | backend only, with **no egress** |

- **Reveal:**
  1. The buyer calls `POST /orders/{id}/reveal`.
  2. The API checks the session and owner, then calls `delivery:8001/internal/reveal` with an internal token (constant-time compare).
  3. Delivery re-checks the owner and the delivered state.
  4. It applies a per-order limit (10/h), a per-buyer limit, and a **global circuit breaker** (30 decrypts/min → 503 + CRITICAL log). A request larger than the remaining budget is rejected before counting.
  5. It writes an audit row and returns the codes with `Cache-Control: no-store`.
- **Lifecycle:** generate with `app.devtools.keygen` (offline in production) → distribute (public key to the API, private key to delivery only) → keep in memory only → back up with age to two offline copies (never in DB backups) → rotate (new `kid` + `rewrap()`) → on **compromise**, revoke, void unsold stock under that `kid`, re-import, notify buyers → destroy. Details: [review-v2 §4](review-v2.md#4-key-isolation-concrete-design).
- **Card import:** `POST /admin/products/{id}/cards/import` is **admin role only**, ≤5000 lines, rate-limited, audited, sealed immediately; plaintext is never echoed. Production adds TOTP step-up and an admin-only network path (M1) and two-person approval for bulk imports (M2).

## 6. Payment pipeline: ZPay Alipay v1

```
pay:    server-priced order ─► signed submit.php URL (no key in URL) ─► buyer pays
notify: GET /api/v1/pay/notify/zpay   (per-IP rate limit; bad-signature audits sampled)
  1 pinned-MD5 signature (constant time) · pid · out_trade_no · TRADE_SUCCESS · exact Decimal amount
  2 Redis replay guard: 60 s IN-FLIGHT lock → promoted to 24 h "done" only after settling
    (a crash mid-settle never blocks ZPay's retries for long)
  3 re-query api.php?act=order (≤3 s total; ZPay waits 5 s): paid, same money, same trade_no, same out_trade_no
  4 BEGIN · order FOR UPDATE · already paid → success · pending → paid
    · late (expired/cancelled, however late) → manual_review, still recorded
    · amount changed after pay URL → manual_review
    · INSERT payments (UNIQUE) · ledger Σ=0 (+ 1.6 % fee txn) · outbox(order.paid) · COMMIT
  5 "success" (also for manual_review, audited) / "fail" (bad sig, outage → ZPay retries)
return_url → display only (redirect to the order page)
```

Prod guards: the gateway and the query base must be `https://`, `APP_COOKIE_SECURE=true`, and the mock gateway refuses to run outside `dev`/`test`. M1 adds a reconciliation job that polls the query API for `pending_payment` orders with a pay attempt, plus external alerting on `manual_review`.

## 7. Chat and negotiation

```
Product "Chat"  → POST /conversations {product_id} → find-or-create + product_card snapshot
Agent "Quote"   → POST /admin/conversations/{id}/quotes → quote (HMAC, expiry, qty≤10 for auto_card) → quote_card
Buyer "Accept"  → POST /quotes/{id}/accept → TX: lock quote, verify → order(pending_payment, quote amount)
Agent "Price"   → PATCH /admin/orders/{id}/price (pending only, ≥ floor×qty, version++, audited, system msg)
Buyer "Pay"     → POST /orders/{id}/pay → ZPay → §6 → delivered (auto) | agent delivers (manual) → confirm
```

- **Message types:** text, image, voice (≤60 s, ≤1 MB, webm/ogg/mp4), product_card, quote_card, order_card, system. When a card's state changes, the server re-publishes the message under the same id, so the client replaces it.
- **Agent status:** online / away / on_hold / offline. Buyers see the best status across agents.
- **Staff Inbox:** filters (all / mine / unassigned), assign, unread counts, close, quote composer, and the buyer's recent orders.
- **Not built:** voice **calls**, which were dropped ([review-v2 §0](review-v2.md#0-what-changed-summary)).

## 8. Security controls

| Threat | Controls (✅ in MVP-0, ⏳ planned) |
|---|---|
| Card-key theft | §5 ✅ |
| Forged or replayed callbacks | §6 ✅; tests cover forged/tampered/wrong pid/downgrade/replay/concurrency/crash-mid-settle/timeout/late |
| Price tampering | Server prices; HMAC quotes; versioned, audited price changes ✅ |
| Cross-tenant access / IDOR | FORCE RLS + per-transaction pinning; owner checks with a uniform 404; cross-tenant tests ✅ |
| Session attacks | Hashed session keys in Redis, rotation on login, HttpOnly, SameSite=Lax, `__Host-` prefix over HTTPS, CSRF header ✅ |
| Brute force / CC | Redis limits: failed logins per (email, ip) + per email; register; messages; uploads; orders, pay and accept per user; ≤5 pending orders per buyer; notify per IP ✅. Edge: Cloudflare / CrowdSec ⏳ M1 |
| Malicious uploads | Magic bytes, single-format decoder, pixel caps, re-encode, EXIF stripped, random keys, `CSP: sandbox`, `nosniff`, voice served as attachment ✅. Separate media origin ⏳ M1 |
| Secret sprawl | Per-service env files, Redis ACL users, column grants, a private-key file only in delivery ✅ |
| Supply chain | SHA-pinned Actions, Dependabot with a 7-day cooldown, pip-audit / pnpm audit, Trivy, gitleaks ✅ |
| On-demand TLS abuse | `ask` endpoint: internal listener, verified domains only, normalization, negative cache, rate limit ✅ (block disabled until M4) |
| Independent audit | ⏳ **M1 exit gate**: no real money before it |

## 10. CI/CD and deployment

| Stage | What runs |
|---|---|
| `backend` | Ruff, pytest against PG 17 + Redis 7 service containers (`TEST_REQUIRE_SERVICES=1`), Bandit, pip-audit |
| `frontend` | Policy lint, vue-tsc, vitest (incl. i18n parity), build + bundle budget |
| `semgrep`, `gitleaks` | SAST and secret scanning (scoped allowlist in `.gitleaks.toml`) |
| `images` | api + web images, Trivy (HIGH/CRITICAL fail the build), saved as artifacts |
| `e2e` | Boots the full compose stack from those exact images, runs `e2e/smoke.py` |
| `publish` | Pushes `:sha` and `:main` to GHCR, only on `main` and only after e2e, Semgrep and gitleaks pass |
| Demo host | Pull-based: `deploy/demo-update.sh` (systemd timer) pulls `:main`, recreates containers and reports a commit status. No inbound CI access to the host. |

Rollback: `git revert` → CI → new `:main`; or pin `API_IMAGE`/`WEB_IMAGE` to a previous `:sha` in `deploy/.env`.
