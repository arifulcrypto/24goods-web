## Payment challenge sources and current gap

- **V:** [Cloudflare server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) documents mandatory server verification, expiring single-use tokens, and optional hostname/action checks appropriate to the integration. **I:** bind 24goods' action/order/session/attempt separately; provider-managed difficulty cannot honestly be exposed as a numeric merchant control.
- **V:** [ALTCHA's PoW description](https://altcha.org/docs/integration/proof-of-work-captcha/) describes client work and inexpensive verification; [complexity documentation](https://altcha.org/it/docs/v2/complexity/) notes device-dependent cost. **I:** self-hosted verification is a compatibility option subject to device benchmarks, accessibility and server-side single-use/binding, not a proof of customer identity.
- **V, local:** `modules/orders/schemas.py:28`, `orders/router.py:90`, `orders/checkout_router.py:104` accept a channel and rate-limit payment initiation, with no challenge call. `core/settings_v5.py:29` and `core/pow.py:27` omit a payment action/scope. **I:** gate every create-attempt path before upstream calls, not payment callbacks/status recovery.

## Operations and security references

- **V:** [1Panel repository](https://github.com/1panel-dev/1panel/) main was resolved to `3c1f2a64b4fe17bbccb904aaac15ee5f5273d41e`. [Dashboard DTO](https://github.com/1Panel-dev/1Panel/blob/3c1f2a64b4fe17bbccb904aaac15ee5f5273d41e/agent/app/dto/dashboard.go) separates host inventory and live CPU/memory/load state; [monitor DTO](https://github.com/1Panel-dev/1Panel/blob/3c1f2a64b4fe17bbccb904aaac15ee5f5273d41e/agent/app/dto/monitor.go) covers resource queries and retention settings. [Official system-log docs](https://docs.fit2cloud.com/1panel/ops/system_logs/) describe level-filtered runtime log access and rotation. **I:** borrow the small overview/task/log presentation, not its broad host-control privileges. No 1Panel code is copied and no package is installed.
- **V:** [Caddy log documentation](https://caddyserver.com/docs/caddyfile/directives/log) documents sensitive credential-header redaction and available query filtering. **I:** retain credential redaction, explicitly filter sensitive query fields, cap volume and render data as text.
- **V:** [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) covers sensitive-data exclusion, untrusted input, injection and operational protection. **I:** collect only needed structured metadata; approximate IP geolocation is not identity proof. Detect several correlated signals rather than treating every crawler or shared IP as an attacker.
- **V:** [OWASP secret-management guidance](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) treats secret lifecycle, least privilege, rotation and revocation together. **I:** maintain review/expiry/authorization metadata and tested rotation/draining procedures; periodic reminders alone cannot make a compromised key safe.
- **V:** [PostgreSQL 17 pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html) provides a consistent database snapshot; it does not itself back up global role objects or external files. [PG continuous archiving](https://www.postgresql.org/docs/17/continuous-archiving.html) combines base backups/WAL for PITR and has explicit incremental-backup prerequisites. **I:** select RPO/RTO first, then test recovery of the complete system rather than labelling every tar/dump an incremental backup.
